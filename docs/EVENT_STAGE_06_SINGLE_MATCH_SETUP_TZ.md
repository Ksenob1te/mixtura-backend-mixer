# ТЗ Для Агента: Этап 6. Одиночные Игры: Матчи И Слоты

## Цель
Реализовать минимальную match-структуру для одиночных игр до внедрения сложных турнирных сеток. После этапа Event Service должен уметь создавать один или несколько последовательных/параллельных одиночных матчей внутри активного события.

## Общий Контекст
- Приоритет реализации: сначала полностью поддержать одиночные игры, затем переходить к tournament bracket algorithms.
- Одиночные игры являются повторяемыми match cycles внутри одного event: во время активного события могут приходить новые игроки, уходить старые игроки, формироваться новые выборки и идти несколько матчей параллельно.
- Создание одиночного матча не должно переводить весь event в глобальный `IN_PROGRESS`. Event остается `ACTIVE`, а состояние идет на уровне `Match`, `Draft`/selection, formation job и `EventPlayer`.
- Сложные форматы `single_elimination`, `double_elimination`, `round_robin`, `swiss` не входят в этот этап.
- Команды и `TeamPlayer` создаются на этапе формирования команд или вручную до создания матча.
- Organizer имеет полную власть над своим мероприятием.
- Server-admin override `event_admin_manage_bracket` может использоваться для административного исправления match setup чужого мероприятия.

## Минимальная Структура
- `Bracket`: контейнер match-структуры события, даже если событие содержит только один матч.
- `Stage`: одна стадия для одиночной игры.
- `StageGroup`: одна группа внутри стадии.
- `Match`: один матч внутри группы.
- `MatchSlot`: fixed slots для команд/участников матча.
- `MatchScore`: stub счета для будущей фиксации результата, если модель предполагает отдельные score-строки.

## SingleMatchSetupUseCase
- Проверить доступ: локальный organizer или server-admin override `event_admin_manage_bracket`.
- Проверить, что event принадлежит `access_data.server_id`.
- Проверить, что event находится в глобальном состоянии `ACTIVE` и не является `COMPLETED`/`CANCELLED`.
- Проверить, что выбранный вариант команд материализован в `Team`/`TeamPlayer` или что команды переданы вручную допустимым способом.
- Создать single-game `Bracket` для event, если его еще нет, и дальше переиспользовать его для всех одиночных матчей этого event.
- Создать одну `Stage` с форматом одиночной игры или нейтральным форматом `single_match`, если такой enum будет добавлен, и дальше переиспользовать ее.
- Создать одну `StageGroup` и дальше переиспользовать ее.
- Создать один `Match`.
- Создать fixed `MatchSlot` для каждой команды матча.
- Создать `MatchScore` stubs, если они нужны текущей модели.
- Связать матч с выборкой, из которой были сформированы команды. Занятость игроков для следующих выборок определяется через активную выборку, связанную с незавершенным матчем.
- Вернуть DTO/result для отображения одиночного матча Gateway-ем.

## Валидация
- Нельзя создать match setup без достаточного числа команд.
- Нельзя смешивать команды из другого `event_id` или `server_id`.
- Нельзя использовать tournament-only settings в single-match setup.
- Если event уже `COMPLETED` или `CANCELLED`, создание match setup запрещено.
- Нельзя использовать выборку, игроки которой уже заняты в другой активной выборке/незавершенном матче, если бизнес-правила не разрешают параллельное участие.

## RPC
- Основной handler: `event.match.setup` или согласованное имя из общего queue naming.
- Handler принимает command DTO с `access_data`, `event_id`, списком `team_id` или ссылкой на выбранный team formation variant.
- Handler возвращает `ResponseMessage[SingleMatchView]` или совместимый result DTO.

## Не Делать
- Не реализовывать `single_elimination`, `double_elimination`, `round_robin`, `swiss`.
- Не реализовывать BYE.
- Не реализовывать standings.
- Не реализовывать продвижение победителей/проигравших по сетке.
- Не фиксировать результаты матчей, кроме создания score stubs.
- Не обновлять рейтинги.
- Не синхронизировать Alembic.
- Не писать и не исправлять тесты; тестирование вынесено в этап 10.

## Критерии Приемки
- Внутри active event можно создать один single-game bracket/stage/group контейнер и один или несколько одиночных матчей с fixed slots команд внутри него.
- Участники активной выборки, связанной с незавершенным матчем, защищены от повторного выбора, если параллельное участие запрещено.
- Match setup готов для фиксации результата на этапе 7.
- RPC handler импортируется и возвращает `ResponseMessage`.
